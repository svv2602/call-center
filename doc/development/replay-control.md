# Реплей сценариев и сравнение прогонов

Два скрипта для проверки «до / после» на наборе сценариев без ожиданий:

- `scripts/replay_scenarios.py` — **платный**: проигрывает сценарии (готовые реплики клиента) через песочницу агента N раз в выбранной сети и дописывает результат построчно;
- `scripts/replay_compare.py` — **бесплатный**: сравнивает два файла результатов (или повторы внутри одного) по структурной подписи хода и раскладывает пары по классам. Выводов о качестве он не делает.

Голдсет (`tests/goldset/`, `scripts/run_goldset.py`) отвечает на вопрос «выполнено ли ожидание». Реплей отвечает на другой: «что изменилось в поведении на тех же репликах» — ожиданий у сценария нет.

## Что реплей проверяет и чего не проверяет

Это пределы инструмента, а не оговорки:

1. **Песочница не исполняет голосовой путь.** Нет `merge_tire_query` пайплайна, нет Fitting FSM, нет обработчиков `src/main.py`, нет STT/TTS. Tools — **моки с ответами по умолчанию** (`src/sandbox/mock_tools.py`). Реплей показывает, какие tools и с какими аргументами зовёт модель, куда переводит и что отвечает, — и только это. Дефект голосового пути реплеем не ловится и не опровергается.
2. **Реплики клиента записаны заранее.** После первого расхождения в ответе бота следующая реплика клиента отвечает на вопрос, которого бот мог не задать. Поэтому расхождение на ходу 1 тянет за собой расхождения на ходах 2–N: считать надо пары, а не ходы, и смотреть на первый разошедшийся ход.
3. **Шум — норма.** Два прохода одного набора на одном и том же коде расходятся сами по себе. В tshina два прохода 173 сценариев расходились структурно в 64.7 % пар — почти целиком из-за одного шумного поля; без него — в 11 %. Отсюда опция `--ignore` и запрет вердиктов: расхождение само по себе ничего не значит, пока не измерен шум.
4. **Оценка стоимости — верхняя граница.** Расход считается по словарю `PRICES` из `scripts/run_goldset.py` над токенами, которые вернул ход; кэш промпта не вычитается, оценка завышена относительно счёта провайдера в 2–3 раза. Кап останавливает по оценке — это безопасная сторона. Фактический расход берут из таблицы `llm_usage_log`.

## Формат сценариев

JSON Lines, одна строка — один сценарий (формат tshina `tireconsultant:simulate`):

```json
{"id": "s001", "locale": "ua", "turns": ["перша репліка клієнта", "друга репліка"]}
```

| Поле | Требование |
|---|---|
| `id` | непустая строка, уникальна в файле (включая пропущенные сценарии) |
| `locale` | `ua` или `ru` — язык реплик клиента; бот отвечает по-украински в любом случае |
| `turns` | непустой список непустых строк |
| `skip` | любое истинное значение — сценарий пропускается |
| прочие поля | игнорируются |

Битая строка, дубль `id`, неизвестная локаль, пустой `turns` — ошибка входа **с номером строки**; прогон не начинается (код возврата 2).

Образец — `tests/goldset/replay/sample.jsonl`: четыре **выдуманных** сценария (оба языка, один с `skip`). `load_cases` голдсета читает только `tests/goldset/cases/*.yaml` и этот файл не подхватывает.

## Где лежит контрольный набор и почему не в репозитории

Контрольный набор собран из реальных звонков колл-центра: `~/call_corpus/batch1/consultant_control/control-set-v1.jsonl` (173 сценария, 432 реплики). **Наборы из реальных звонков и чатов лежат вне репозитория и в репозиторий не кладутся** — в них реплики клиентов. В репозитории — только выдуманный образец.

То же относится к **файлу результата**: в него пишутся реплики клиента. Для набора из реальных звонков файл результата обязан лежать вне репозитория. Путей по умолчанию у скрипта нет; путь `--out` внутри репозитория скрипт отклоняет как ошибку входа.

## Проигрывание: `scripts/replay_scenarios.py`

Запускается в контейнере `call-processor` (нужны БД для промпта и ключи провайдеров). **В контейнере нет каталога `tests/`** — набор копируют `docker cp` и передают путь опцией.

```bash
docker cp <набор.jsonl> call-center-call-processor-1:/tmp/replay-set.jsonl

# бесплатно, без БД: загрузить набор, показать, сколько пар осталось
docker exec call-center-call-processor-1 python -m scripts.replay_scenarios \
    --scenarios /tmp/replay-set.jsonl --out /tmp/replay-a.jsonl \
    --network tvoya-shina --sales-enabled on --cap-usd 5 --validate

# план и оценка стоимости (нужна БД, LLM не вызывается)
docker exec call-center-call-processor-1 python -m scripts.replay_scenarios \
    --scenarios /tmp/replay-set.jsonl --out /tmp/replay-a.jsonl \
    --network tvoya-shina --sales-enabled on --cap-usd 5

# платный прогон
docker exec call-center-call-processor-1 python -m scripts.replay_scenarios \
    --scenarios /tmp/replay-set.jsonl --out /tmp/replay-a.jsonl \
    --network tvoya-shina --sales-enabled on --cap-usd 5 --yes

docker cp call-center-call-processor-1:/tmp/replay-a.jsonl <каталог вне репозитория>/
```

| Опция | Значение |
|---|---|
| `--scenarios` (обязательная) | файл набора |
| `--out` (обязательная) | файл результата, **дописывается**; вне репозитория |
| `--network` (обязательная) | `tvoya-shina`, `prokoleso` или `both` |
| `--sales-enabled` (обязательная) | `on` / `off` — значение `sales_enabled` тенанта; от него зависит набор tools |
| `--cap-usd` (обязательная) | кап расхода в долларах |
| `--runs N` | число проходов по набору, по умолчанию 1 |
| `--max-consecutive-errors N` | сколько пар подряд со сбоем LLM останавливают прогон, по умолчанию 3 |
| `--provider` | ключ провайдера в LLM-роутере; по умолчанию — `agent_provider_override` тенанта |
| `--input-tokens-per-turn` | входных токенов на реплику для оценки плана, по умолчанию как у голдсета |
| `--validate` | только загрузить набор и напечатать план, без БД |
| `--yes` | запустить платный прогон; без неё скрипт печатает план с оценкой и выходит |

**Ключ пары** — `(id, network, run)`. Поле `run` — номер прохода по набору, с 1. Это **не** `Run` голдсет-харнесса (там `Run` — пара «кейс × сеть», а повтор называется `repeat`). Проход — это весь набор целиком: сначала все пары в первый раз, потом во второй, так что повторы одной пары разнесены во времени. У каждой пары свой агент и пустая история.

**Возобновление.** Пары, ключ которых уже есть в файле результата, пропускаются: прерванный прогон продолжается тем же вызовом. Файл, записанный с другим `sales_enabled`, отклоняется — для другого режима нужен другой файл.

**Кап.** До старта печатаются план и оценка. Прогон останавливается перед очередной парой, когда расход достиг **80 %** капа; расход уже записанных строк файла учитывается. Стоимость пары, потерянной из-за сбоя LLM, учитывается до конца текущего вызова (в файл она не попадает). Модель без цены в `PRICES` — ошибка входа: кап не может работать.

`--cap-usd` задаётся **в долларах оценки, а не счёта провайдера**. По умолчанию план считает 55 000 входных токенов на реплику (как голдсет): для набора в 432 реплики на `gpt-4.1-mini` это ≈ $9.6 на сеть, тогда как счёт провайдера за тот же проход — около $2.6. Чтобы проход дошёл до конца, 80 % капа должны быть не меньше оценки; если кап остановил прогон раньше (код 3), тот же вызов с большим `--cap-usd` продолжит с места остановки.

**Сбой LLM.** Пара, в которой хоть один ход закончился ошибкой LLM (`TurnObservation.error`), в файл **не пишется** — в базу сравнения она не годится — и будет переиграна следующим вызовом. Пара обрывается на ходу с ошибкой. Несколько таких пар подряд останавливают прогон; чистая пара обнуляет счётчик.

**Коды возврата:** 0 — все пары записаны (либо платный прогон не запускался); 2 — ошибка входа; 3 — остановка по капу; 4 — есть пары, потерянные из-за сбоя LLM. Если причин несколько, возвращается первая из 2 → 3 → 4.

### Строка результата

```json
{"id": "s001", "network": "tvoya-shina", "run": 1, "locale": "ua", "sales_enabled": true,
 "model": "gpt-4.1-mini", "played_at": "2026-11-20T10:00:00+00:00",
 "turns": [{"user": "…", "response": "…",
            "tool_calls": [{"name": "search_tires", "args": {"size": "205/55 R16"}}],
            "transfer_reason": null, "error": null, "input_tokens": 41000, "output_tokens": 60}],
 "input_tokens": 41000, "output_tokens": 60, "cost_usd": 0.016496}
```

Поля хода `user`, `response`, `tool_calls` совпадают с записью `--json-out` голдсета; скрипт сравнения читает и её (`case` / `repeat` принимаются вместо `id` / `run`, ошибка хода берётся из `failed[].name == "turn_error"`).

## Сравнение: `scripts/replay_compare.py`

Работает на рабочей машине над файлами, скопированными из контейнера: без БД, без ключей, без LLM, модули `src` не импортирует.

```bash
# два прогона: «до» и «после»
python -m scripts.replay_compare <до.jsonl> <после.jsonl>

# без шумного поля, с текстами ответов
python -m scripts.replay_compare <до.jsonl> <после.jsonl> --ignore tool_args.search_tires.query --show-text

# повторы внутри одного файла (прогон с --runs N)
python -m scripts.replay_compare --within <прогон.jsonl>
```

Пары сопоставляются **по ключу** `(id, network, run)`, а не по номеру строки: файл дописывается, после возобновления порядок строк другой.

### Подпись хода

Подпись — то, что решают код и модель, а не формулировка:

| Поле | Что это | Можно исключить |
|---|---|---|
| `tools` | имена tools по порядку вызова | да |
| `tool_args` | аргументы каждого вызова по порядку | да, целиком, по одному tool (`tool_args.<tool>`) или по одному аргументу (`tool_args.<tool>.<arg>`) |
| `transfer_reason` | причина `transfer_to_operator`, если перевод был | да |
| `turn_count` | число ходов в паре | **нет** |
| `user` | реплики клиента (разные — значит, между прогонами изменился сам набор) | **нет** |
| `error` | наличие ошибки хода | **нет** |

Аргументы перед сравнением нормализуются — порядок ключей и подряд идущие пробелы — **без потери значений**: `205/55 R16` и `205/55R16` — разные аргументы, это структурное расхождение. Текст ответа в подпись не входит и сравнивается отдельно.

`--ignore FIELD` (можно несколько раз) убирает поле из подписи. Неизвестное имя, попытка исключить `turn_count` / `user` / `error`, а также `tool_args.<tool>[.<arg>]`, которых нет ни в одном из файлов (опечатка), — ошибка входа. Отчёт называет исключённые поля в заголовке и в итоговой строке. Поля независимы: причина перевода видна и в `transfer_reason`, и в `tool_args` вызова `transfer_to_operator` — чтобы убрать её целиком, исключают оба.

### Классы

| Класс | Значение |
|---|---|
| `identical` | подпись и тексты ответов равны |
| `text_only` | подпись равна, формулировка разная |
| `structural` | подпись разная; отчёт называет поле и ход |
| `error` | в любой из двух записей есть ход с ошибкой LLM — пара несравнима |
| `missing` | ключ есть только в одном файле (в `--within` — у группы один повтор) |

Порядок: `missing` → `error` → `structural` → `text_only` → `identical`.

Отчёт: число пар по классам, разбивка по сетям, расхождения по полям, список структурных пар с первым разошедшимся значением; `--show-text` добавляет реплики и ответы. В режиме `--within` единица — группа «сценарий × сеть»: «однаковий підпис 2 з 3» значит, что два повтора из трёх дали одну подпись.

**Скрипт назначает только классы.** Он не называет расхождение ни хорошим, ни плохим, и код возврата от классов не зависит (0 — сравнение выполнено, 2 — ошибка входа).

## Правило «до / после»

1. **Сначала измерить шум.** Два прохода набора на одном коммите в одной сети (`--runs 2` и `--within`, либо два файла): доля `structural` — с полной подписью и с исключёнными шумными полями — это инкумбент. Без него цифра «после» ничего не значит.
2. Прогон «после» сравнивают с прогоном «до» в той же сети, с тем же `sales_enabled`, тем же набором и теми же `--ignore`.
3. Доля `structural` в пределах шума — изменение на этом наборе неотличимо от шума. Выше шума — это повод **открыть пары руками** (`--show-text`), начиная с первого разошедшегося хода; класс сам по себе не вывод.
4. Пары `error` и `missing` в долю не входят: первые несравнимы, вторые не сыграны. Если их много — доиграть прогон тем же вызовом, а не сравнивать.
5. Помнить о пределах: реплей не видит голосового пути, а tools отвечают моками.
